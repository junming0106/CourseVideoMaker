# 上課節奏標準

怎麼切段落、怎麼等學生、檢查點放哪裡。
從 2A5（貓抓老鼠，1~3 年級，24 分鐘）實作後收斂出來的規範，含實際踩過的錯誤。

---

## 一、課程骨架

八個章節，每章開頭一張章節卡。順序不要動：

| 章 | 作用 | 為什麼在這 |
|---|---|---|
| 1 開場 | **痛點提問 → 先播成品** | 見下節「開場三秒法則」——自我介紹不算引起動機 |
| 2 核心概念 | 一個最重要的觀念（如「如果」） | 抽象的先講，後面才有東西可套 |
| 3 認識工具 | 打開軟體、認識介面 | 概念懂了才有動機學工具 |
| 4~6 分段實作 | 每段＝一個角色／一個功能 | 一次只做一件事 |
| 7 表達訓練 | 上台分享、情緒引導 | 非技術能力，換腦袋 |
| 8 複習 | 一次一題回顧，**並回扣開場的痛點** | 收尾要具體，不要只說「今天很棒」；見七之二 |

## 一之二、開場三秒法則

**影片的前 3 秒必須是一個學生答不出來的問題，或一個他正在遇到的麻煩。**

學生退出影片最多的位置就是開頭。他還沒決定要不要看，你卻在播校徽動畫、
唸「大家好我是某某老師」、介紹兩個他還不認識的配角——這些都是他點下一支影片的理由。

### 前 15 秒的配置（而且要用「實際時間」驗證）

> ⚠ **別只看前三句台詞就說符合。** 2A1 初稿「第一句是痛點、沒有問候」，但實際學習目標在 **42 秒**才開口：
> 前兩段話太多，加上**每個段落之間 LEAD＋TAIL 會多 1.6 秒緩衝**，Voai 的語速又比字數估算慢。
> 處理方式：(1) 開場前幾段把 `lead`／`tail` 縮到 0.15；(2) 前兩段各只留 2 句；(3) 自我介紹併進學習目標後面那一句（`我是 Cooper 老師，我們先看看今天的四個任務`）；
> (4) **build 自己算學習目標的開口秒數，超過 15.5 秒就報錯**（2A1 的 `build-composition.mjs` 開頭有範例）。



| 秒 | 內容 |
|---|---|
| 0.0~0.5 | 第一句話已經在講，**不留空拍**，畫面同時出現痛點字卡 |
| 0~3 | **痛點提問**（「為什麼你的貓咪怎麼點都不會動？」）＋ hold 2 秒 |
| 3~8 | 直接播今天要做出來的成品畫面，「這堂課結束你就會做這個」 |
| 8~12 | 這時候才自我介紹，一句話帶過 |
| 12~15 | **學習目標**一句話：「看完你會做出 X，也會知道 Y」（Y＝開場痛點的答案，見七之二） |
| 15~ | 進第一個概念 |

### 硬性規定

- **片頭動畫最長 2 秒，而且不可以放在第一句之前**——要放就疊在痛點句底下當背景。
  2A5 用了 5 秒的 `intro.mp4` 放在最前面，等於把最貴的 5 秒送給了片頭。
- **章節卡不可以是全片的第一個畫面**。第 1 章的章節卡挪到痛點句之後。
- **問候最多一句、≤2 秒（使用者要求直接開講太突兀）**，緊接著痛點提問；原本「第一句不可以是問候語」放寬成這樣。自我介紹仍排在學習目標之後。
- （舊規則，已放寬）第一句不可以是問候語。「小朋友大家好」「我是 Cooper 老師」「今天要上什麼呀」
  這三句連著講掉了 10 秒，全都不是內容。
- 痛點句要是**學生自己會遇到的具體狀況**，不是課程目標的改寫。
  ✗「今天我們要學會條件判斷」 ✓「為什麼貓咪撞到牆還一直往前走？」

### 三種好用的開場句型

| 型 | 例 |
|---|---|
| 失敗現象 | 「為什麼你的貓咪怎麼點都不會動？」 |
| 反常識 | 「這三塊積木換個順序，遊戲就壞了。你猜是哪一塊？」 |
| 先給成品 | 「三十分鐘後，你會做出這個。」（直接播成品，播完才說話）|

## 一之三、視覺設計規範

### 字型：只用圓體與黑體

`FONT_CSS`（在 `tools/lib/cards.mjs`）已經定好，直接內嵌，不要自己寫 `font-family`。

- **禁止新細明體、細明體、標楷體。** 明體的橫細直粗在 1080p 上會斷筆畫；
  楷體在螢幕上讀起來像公文，兩者對這個年齡層都是負面訊號。
- 字重一律 **800 以上**。教學影片會被投在教室單槍上，細字直接消失。
- 內文字級最小 34px（`size: 'sm'`）。再小低年級看不清楚。

### 關鍵字要標出來

一句話裡的重點詞用 `hi()` 放大 22% ＋ 換色：

```js
card({ text: `程式要寫在 ${hi('貓咪', 'white')} 身上`, tone: 'orange', size: 'md', fx: 'pop', at: 3.2 })
```

**一句只標一個詞**——標兩個以上等於沒標。黃底卡片上只有 `navy` 讀得清楚。

放大倍率與顏色不是寫死的：`hi('詞', { color: '#FF00AA', scale: 1.9 })` 可以逐句覆寫，
整片要統一調就改 `cards.mjs` 的 `HI_DEFAULT`。

### 不要把投影片錄成影片

教案的 PPT 是**內容來源**，不是畫面來源。整頁貼上去等於叫學生自己讀，
而低年級學生不會讀畫面上的字，他們只看會動的東西。

| 要呈現的東西 | 不要 | 要 |
|---|---|---|
| 一個概念 | 貼整頁投影片 | CSS 畫的示意圖＋逐項 `fx()` 進場 |
| 一段程式 | 整張截圖擺著 | 截圖＋`circle()` 圈出正在講的那塊 |
| 一個步驟 | 講「按左上角那個」 | `arrow()` 指過去 |
| 一個名詞 | 唸過去 | `underline()` 畫線＋`hi()` 變色 |

### 視線引導：三種指法

`tools/lib/pointers.mjs` 的 `arrow` / `circle` / `underline`，分工不要混：

| 用哪個 | 指什麼 |
|---|---|
| `arrow` | 單一小目標（一顆積木、一個按鈕）|
| `circle` | 一小群東西（一整段程式、一組數字）|
| `underline` | 一行字（標題、句子裡的關鍵詞）|

**畫面上同時只能有一個引導**。兩個箭頭指兩個地方，等於沒有引導。

## 二、段落切分：一段只講一件事

| 段落類型 | 句數 | 說明 |
|---|---|---|
| 章節卡 | 1 句 | 只有大圖卡與旁白，不出角色 |
| 概念講解 | 6~8 句 | 一個概念配一個生活比喻 |
| **實作示範** | 6~8 句 | 概念講完立刻演一次（見下節）|
| 程式碼展示 | 5~7 句 | 逐塊講解，配紅框 |
| 練習題 | 4~6 句 | 出題 → 倒數 → 公布 → 講解 |

**判斷是否該切開**：如果一段裡出現「另外還有⋯」「再來我們看⋯」，就該切成兩段。

## 三、核心節奏：概念 → 立刻操作

**每個概念講完，馬上接一段實機操作示範。** 不要把所有操作堆在影片後半。

```
概念（這是什麼、為什麼）
   ↓
實作示範（真的畫面、真的點哪裡）
   ↓
練習題（換你想）
```

2A5 的實際配置：9 段概念各自對應 1 段實作示範，插在概念之後、程式碼展示之前。

### 實作示範段的公式

```
① 開場句      「說完了，我們真的做一次給你看。」
② 3~6 個步驟   一步一句台詞，一句配一張真實截圖＋紅框
③ 學生驚呼     Max 或 Cora 講一句反應（避免整段老師獨白）
④ 收尾指令     「你也做到了嗎？沒有的話先暫停影片。」+ hold 4~5 秒
```

**截圖不要超過 6 張**。步驟太多就拆成兩段，不然學生跟不上。

## 四、等待學生：只有「需要想」的才停

**先決定要不要停，再決定停幾秒。** 使用者的回饋：「問問題的地方可以直接交給夥伴回答，比較重大的問題，像是確認是不是學會程式觀念、問考題等才要等待時間」。

| 要停 | 不要停（夥伴直接答） |
|---|---|
| 練習題、複習題 | 一問一答就能解決的小問題 |
| 「猜猜看」變化題（先猜再驗證） | 反問句（「想不想做一隻？」） |
| 回扣開場問題（驗收學會沒） | 看示範的停頓 |
| 必須動手（跟著操作、抄程式） | 沒有標準答案的問題（「你最想畫什麼？」） |

停頓顯示成**黑板正中央的手繪鬧鐘＋倒數秒數**（見 visual-style.md 第四節），畫面中間要先留空。
2A1 第一版 52 處停頓，使用者看了覺得拖，最後只留 22 處（約 103 秒）。

秒數分級（只適用於「要停」的那些）：

停頓不是隨便給，秒數對應不同的認知負荷：

| 情境 | 秒數 | 例 |
|---|---|---|
| 簡單回想 | 2~3 | 「你今天早上桌上有早餐嗎？」 |
| 需要思考的提問 | 3~5 | 「這三塊積木的順序可以換嗎？」 |
| 跟著操作 | 4~5 | 「你也打開了嗎？」 |
| 照著抄寫程式 | 6 | 「暫停影片，照著螢幕排排看。」 |
| 帶做練習 | 12 | 呼吸法，且要做滿兩輪 |

**時長要靠內容撐，不是靠拉長停頓。** 每句停 5 秒只會讓畫面看起來卡住。

## 五、提問四拍法則（最常犯錯的地方）

任何提問，都必須走完四拍（**停頓這一拍只有「重大問題」才真的停，見第四節**；其他問題把停頓拿掉，仍然要有學生回答與老師講解）：

```
① 老師提問  →  ② 停頓  →  ③ 學生角色回答  →  ④ 老師講解為什麼
```

**2A5 初版漏掉第③④拍共 7 處**，變成「問完停 4 秒，然後直接換話題」，學生停在那裡永遠不知道答案。

錯誤示範：
```js
{ who: 'Cooper', action: 'thinking', text: '這三塊積木的順序可以換嗎？', hold: 4 },
{ who: 'Cora',   action: 'talking',  text: '這樣貓咪就會一直追著老鼠跑了！' },  // ← 答非所問
```

正確：
```js
{ who: 'Cooper', action: 'thinking',     text: '這三塊積木的順序，可以換嗎？', hold: 4 },
{ who: 'Max',    action: 'thinking',     text: '應該可以吧？反正三塊都在裡面。' },  // 先猜錯
{ who: 'Cooper', action: 'talking',      text: '不行喔，換了順序就會出問題。' },
{ who: 'Cooper', action: 'guide_right',  text: '一定要先面向老鼠，才往前走。' },
{ who: 'Cora',   action: 'listening',    text: '不然貓咪會朝著舊的方向走。' },
{ who: 'Cooper', action: 'talking',      text: '對，就追不到了。程式是有先後順序的。' },
```

**讓配角先猜錯，老師再糾正** —— 這比老師直接講答案好，因為學生的直覺往往跟 Max 一樣。

### 例外：帶做確認語不需要答案

```js
{ who: 'Cooper', action: 'thinking', text: '你也打開了嗎？沒有的話先暫停影片。', hold: 4 },
```

這種停頓是給學生跟上進度，本來就沒有標準答案，**不算違規**。

用 `scripts/check-questions.py` 可自動複查，它會排除這一類。

## 六、檢查點：三種，作用不同

| 類型 | 放哪裡 | 目的 |
|---|---|---|
| **跟上確認** | 每段實作示範結尾 | 「你也做到了嗎？」給落後的學生追上 |
| **練習題** | 每個大章節後 | 驗收剛學的概念 |
| **複習題** | 影片最後 | 一次一塊積木，猜用途 → 說答案 |

### 選項題：畫面和旁白必須是同一套語言

2A5 踩過：畫面是 **A／B 兩張選項卡**，旁白卻問「要按哪一個**顏色**？」，答案回「**綠色**」。學生看到 A、B 卻聽到用顏色作答，不知道該怎麼回應。

規則：畫面標了 A/B，旁白就要唸出「**A 是⋯，B 是⋯**」，學生角色就要回「**我選 A**」。

## 七、易錯點要正面處理，不要迴避

學生會犯的錯，**直接演給他看為什麼錯**，比只講正確做法有效。

2A5 的三個例子：

| 易錯點 | 處理方式 |
|---|---|
| 程式寫在哪個角色 | 切到另一個角色，讓學生看到**程式區是空的** |
| 變數預設叫 `my variable` | 讓學生看到預設值，再親手改成 `score` |
| 以為計分要寫在背景 | 點開舞台，證明**偵測區裡根本沒有那塊積木** |

這類段落的價值最高——它回答的是學生真的會卡住的問題，不是教案上寫的問題。

## 七之二、四個加分設計

這四項是「好的兒童教學」和「把教案唸完」的差別。1、2 是硬性（審稿會擋），3、4 是軟性（審稿提建議）。
語氣怎麼配（`tone`／`lead`）見 SKILL.md「配音語氣」。

### 1. 學習目標 ＋ 結尾回扣（硬性）

開場痛點拋出、成品播完之後，**用一句話講出這堂課結束你會做到什麼**；
複習的最後，**把開場的痛點原句再問一次，讓學生角色自己答出來**，並指出是哪一步解決的。

```
開頭：「看完這支影片，你會自己做出貓抓老鼠，也會知道貓咪為什麼會撞牆還一直走。」
結尾：Cooper「還記得一開始的問題嗎？貓咪為什麼撞牆還一直走？」
      Max「因為沒有用『如果碰到牆壁』去偵測！」
      Cooper「答對了，就是第三章的那塊積木。」
```

- 學習目標只能一句、不超過 30 字，**不要列清單**（低年級聽不完）
- 目標裡的「知道 Y」必須是開場那個問題的答案，結尾才接得回來
- 回扣要用**同一句話**問，不要換個說法，不然學生聽不出是同一題

### 2. 變化題：改一個參數看看會怎樣（硬性）

「示範 → 跟做」之後缺一步：**自己改一處、先猜、再驗證**。這是從模仿走到理解的關鍵。
第 4~6 章（分段實作）**每章至少一題**，放在「你也做到了嗎」之後。

走完四拍：

1. 老師出題：「把速度從 10 改成 50，貓咪會怎樣？」
2. 停頓 3~4 秒（`hold`）
3. 學生角色猜：「會跑超快！」
4. 實際演示，老師講解：「對，數字越大，走得越快。」

- **一次只能改一處**，改兩個地方學生分不出是哪個造成的
- 改完要**看得出差別**（10→50，不是 10→11）
- 一定要先猜再驗證，直接演示不算變化題

### 3. 具體鼓勵，不要空泛稱讚（軟性）

稱讚要**點名行為，並說出那個行為的意義**，學生才知道哪個做法值得重複。

| ✗ 空泛 | ✓ 具體 |
|---|---|
| 「你好棒！」 | 「你自己發現順序要對調，這就是除錯！」 |
| 「太厲害了！」 | 「你先猜了再按綠旗，工程師都是這樣做的。」 |
| 「答對了！」 | 「答對了，你抓到重點：碰到才會加分。」 |

「好棒」「太厲害」可以當開頭的語氣詞，**後面一定要接具體的那句**，不可以單獨成句。

### 4. 錯誤正常化（軟性）

學生角色犯錯、或程式跑出怪結果時，老師要講**三件事**，缺一不可：

1. **這很正常**：「這個錯很多人都會遇到。」
2. **錯在哪裡**：正面演示（見七），不要只說「錯了」
3. **下一步怎麼辦**：「我們來檢查積木順序。」

- **不要說「錯了」「不對」當第一句**，先接住情緒
- 每堂課至少一次由 Cooper 明講：「程式出錯很正常，找出哪裡錯，就是工程師每天的工作。」
  放在第一個易錯點的段落，之後的錯誤就不用每次重講
- 學生角色犯錯時配 `tone`（例如 Max：`sheepish and a little embarrassed`），Cooper 回應配 `gentle and reassuring`

## 八、語言：1~3 年級

- **一句一個意思**，不要有「而且」「但是」串接
- **先具體再抽象**：門鈴 → 偵測、收納箱 → 變數、跑操場 → 迴圈
- **數字用國字唸**：「百分之八十」不是「80%」（TTS 會唸錯）
- **不要說「程式碼」「執行」「參數」**，說「積木」「跑跑看」「數字」

比喻對照表（2A5 已驗證好用）：

| 概念 | 比喻 |
|---|---|
| 條件判斷 | 選路、早餐流程圖 |
| 偵測 | 門鈴（按下去才會響）|
