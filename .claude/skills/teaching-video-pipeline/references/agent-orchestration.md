# Agent 分工與閘門

哪些工作該開 Agent、哪些用腳本、閘門怎麼判定、重試上限。

---

## 第一原則：能用腳本就別開 Agent

Agent 是冷啟動，要重新理解脈絡，成本高。**分界線是「需不需要看著東西做判斷」。**

| 工作 | 用什麼 | 為什麼 |
|---|---|---|
| 三個角色配音 | `gen-voice.mjs ×3`，**串行** | 純執行，零判斷；併發會被 API 擋（見下） |
| 裁程式碼圖、量紅框座標 | `crop-code.py` / `measure-code.py` | 機械性計算 |
| lint、提問收尾複查 | `hyperframes lint` / `check-questions.py` | 判準明確可程式化 |
| 抽出紅框影格 | `check-frames.mjs` | 只是截圖，不做判斷 |
| **拍實機操作截圖** | **Agent** | 要開瀏覽器、看畫面、判斷這步對不對 |
| **審核講稿** | **Agent** | 要理解教案、判斷正確性與語氣 |
| **判讀紅框影格** | **Agent** | 要看圖判斷「框有沒有指到該指的東西」 |

一堂課真正該開 Agent 的只有三處。

### ⚠️ 「寫入不衝突」不等於「可以同時跑」

2A4 踩過：三個角色的配音**寫入目標**確實互不干擾，於是用 shell `&` 同時跑三個進程。
但每個 `gen-voice.mjs` 內部就併發 4 條，三個一起＝ **12 條打向 voai**，311 句掉了 52 句。

判斷平行時要同時看兩件事：**寫入目標會不會撞**，以及**外部資源（API 配額／速率）撐不撐得住**。
只檢查前者就放手平行，是這條產線最貴的錯——掉句是靜默的，發現時配額已經花掉了。

## Agent A：素材採集（階段 ④）

**任務**：在教學系統實機操作一輪，逐步截圖。

**輸入**：教案原文（角色、背景、每頁的程式）＋ 定稿講稿的實作段落清單
**輸出**：`hyperframes-project/assets/steps/*.jpg`（1620px 寬，JPEG q88）

### ⚠️ 不可再拆給多個 Agent

操作截圖是**一條連續的狀態流**——先刪角色才能加貓、先加貓才能寫貓的程式。
兩個 Agent 同時操作同一個專案只會互相破壞。**這條線內部必須串行。**

### 開工前必須先確認的規格

2A5 因為沒先問清楚，重拍了兩輪：

- 介面語言（中文／英文）
- 主題（深色／淺色）
- 用哪個帳號（**示範帳號，不要用真人學生帳號**——會拍到姓名與等級）
- 截圖尺寸（瀏覽器視窗高度有上限，先實測再決定寬度，否則比例會被拉扁）
- **教案提到的角色／背景在系統裡還在不在**（2A4：教案的 `Sprite1` 已因商標下架，只有 `Cat 2`）

### 用哪個工具拍：chrome-devtools MCP

**可以直接開瀏覽器邊操作邊截圖，不必人工手動拍。** 但要挑對工具：

| 工具 | 能不能用來拍步驟圖 |
|---|---|
| `mcp__chrome-devtools__*` | ✅ **用這個**。`take_screenshot` 的 `filePath` 會寫出**原始解析度 PNG 檔**，`crop-step.py` 直接吃得到 |
| `mcp__Claude_Browser__*` | ⚠️ 只能看，不能拍。它的 `computer{screenshot}` 是回傳縮圖給模型，不落檔，拿不到 2496px 的原圖 |

固定流程：

```
navigate_page      → https://exam.codepro123.online/playground/practice/
（使用者自己登入）
evaluate_script    → 設 iframe 寬度 1248，取得 vm / ScratchBlocks
evaluate_script    → 疊上這一步的積木
take_screenshot    → filePath: 存成 PNG（DPR 2，原始解析度）
python3 crop-step.py <png> <名稱>.jpg   → 裁成 1620×911 存進 assets/steps/
```

`evaluate_script` 是**同源**的，所以從最上層就能拿到 iframe 內部：

```js
() => {
  const w = document.querySelector('#pg-scratch-iframe').contentWindow;
  w.document.querySelector('html');          // TurboWarp 的 DOM
  return { hasVM: !!w.vm, hasSB: !!w.ScratchBlocks };
}
```

> ⚠️ **帳號密碼一律由使用者自己輸入。** Agent 不代打帳密，也不要求使用者把密碼貼進對話。
> 請使用者先登入好，登入後 Agent 才接手操作。示範帳號是 `test-student-01`，
> **不要用真人學生帳號**——畫面上會拍到姓名與等級。

### CodeBrainy 系統的實拍要點

**完整操作步驟見 [codebrainy-capture.md](codebrainy-capture.md)** — 網址、iframe 結構、
16:9 尺寸、疊積木的 API 寫法、裁切與命名慣例都在那份，換一台電腦照著跑就行。

這裡只留編排上要知道的兩件事：

- 高度鎖死在 702px，**只能改寬度**（`iframe.style.width = '1248px'`）
- 積木**不能用滑鼠拖**，Blockly 吃不到合成事件，要走 `ScratchBlocks` API

### 一定要等講稿定稿才開拍

2A5 邊拍邊想，拍了 37 張只用約 30 張。**稿定了才知道哪一步只講一句、不需要單獨一張圖。**

## Agent B：講稿審核（閘門 ③）

**輸入**：教案原文 ＋ 產出的 `grade1-3.md`
**不要給**：寫稿 Agent 的推理過程——否則它會被對方的理由說服而放行

**輸出格式**：

```
判定：PASS / FAIL
FAIL 項目：<條號>
  位置：script-data.mjs:327
  問題：<具體描述>
  建議：<怎麼改>
```

### 硬性項目（任一 FAIL 就退回重寫）

1. **提問有停頓卻沒有收尾** — 提問→停頓→**學生回答**→**老師講解**四拍要走完
   （2A5 初版漏了 7 處；`check-questions.py` 可先機器過濾一輪）
2. **對話接錯話** — 某句在回應的是兩句前的內容
   （2A5：Max 的「零分！」實際在回應更早的台詞，中間被插入的提問切斷）
3. **教學內容與教案不符** — 特別是程式寫在哪個角色、積木順序、數值
4. **術語前後不一致** — 例如 `my variable` 與 `score` 混用
5. **紅框關鍵字不唯一** — `shots[].on` 的字串若在同段落重複，畫面會綁錯句
6. **選項題的畫面與旁白不同語言** — 畫面標 A/B，旁白就要唸「A 是⋯B 是⋯」，
   學生角色要回「我選 A」，不可以用顏色或內容作答
   （2A5 的 5:08 踩過）

7. **開場沒有在 3 秒內拋出痛點** — 第一句是問候語、片頭動畫超過 2 秒、
   或第一個畫面是章節卡，都算 FAIL。這是學生退出率最高的位置，
   判準明確（看前三句台詞與 `intro` 長度），所以放在硬性而不是軟性。
8. **重點字卡沒有標關鍵字** — 每張說明卡都要用 `hi()` 標出一個詞，且**只能一個**
9. **講到「按這裡／看這塊」卻沒有視線引導** — 要配 `arrow`／`circle`／`underline`，
   而且同一時間只能有一個

### 軟性項目（提出建議，不擋）

- 句長與用詞是否適合目標年級
- 三個角色語氣是否一致（Cooper 老師／Max 好奇搗蛋／Cora 貼心附和）
- 節奏會不會太平（連續 4 句以上同一角色獨白）
- 有不有趣

> **「有趣」不能當主要判準。** 它沒有 ground truth，模型多半會回「生動活潑」然後放行。
> 2A5 這關真正擋下的全是教學正確性問題，不是趣味性。

## Agent C：影格判讀（閘門 ⑥）

**前置**：先跑 `node ../../../tools/qc/check-frames.mjs`（在課程的 `scripts/` 底下執行），它會自動抽出每個紅框出現的那一格
（2A5 共 46 張，涵蓋實作示範與程式碼展示的所有紅框）。

**輸入**：`output/frame-check/*.png` ＋ 對應的台詞
**輸出**：逐張 OK / NG，NG 要寫出「框到了什麼、應該框什麼」

**可以分給多個 Agent**：46 張切成 3~4 份平行判讀，彼此無關聯。

### 常見的三種 NG（2A5 全都出現過）

| 症狀 | 例 |
|---|---|
| 框到空白處 | 用了「操作後」的截圖，但旁白說「按那個按鈕」——按鈕已經不在畫面上 |
| 框太大沒指到目標 | 框住整個程式區，但旁白說的是「那個小箭頭」 |
| 被畫面元素遮住 | 框放在最左側，被 Cooper 的對話框整個蓋住 |

## 閘門與重試上限

| 閘門 | 上限 | 超過怎麼辦 |
|---|---|---|
| ③ 講稿審核 | **3 次** | 停止產線，輸出報告 |
| ⑥ 影格判讀 | **2 次** | 停止產線，輸出報告 |

**規則：**

- **不強制放行**。超過上限就停，強制通過等於閘門失效。
- **原地打轉偵測**：若第 2 輪的 FAIL 項目與第 1 輪完全相同，代表沒讀懂退稿理由，
  **提前中止**，不必耗到第 3 次。
- **帶累積的 FAIL 清單**重寫，不是只帶這一輪的——否則會出現
  「第 1 輪修好 A 弄壞 B、第 2 輪修好 B 又弄壞 A」。
- 每輪寫進 `review-log.json`：輪次、判定、FAIL 項目、當輪講稿的雜湊，
  中止時能一眼看出卡在哪。

## 什麼情況不要開 Agent

| 不要拆 | 原因 |
|---|---|
| **寫稿分章節給多人** | 角色語氣會飄、紅框關鍵字會撞、前後呼應會斷 |
| **操作截圖分多人** | 狀態流互相依賴，會打架 |
| **渲染中同時做檢查** | 檢查是閘門，發現問題就要重跑 18 分鐘的渲染；且渲染會吃滿 4 個 worker + GPU |

**真的能跟渲染平行的是「下一堂課的前段工作」**，不是這堂課的檢查。

## 完整編排

```
① 讀教案（人／主 Agent）
      ↓
② 寫大綱＋講稿（主 Agent，不可拆）
      ↓
③ ★閘門★ Agent B 審核 ──FAIL──→ 退回 ②（≤3 次）
      ↓ PASS
④ ├─ Agent A：素材採集（內部串行）
   └─ shell：gen-voice ×3 **串行**（併發會掉句，見下）
      ↓ 合流
⑤ 回填紅框座標 → build-composition → mk-audio-bed → lint
      ↓
⑥ ★閘門★ check-frames.mjs → Agent C×N 判讀 ──FAIL──→ 退回 ⑤（≤2 次）
      ↓ PASS
⑦ 渲染（同時可開下一堂課的 ①②）
      ↓
⑧ 成品抽驗（ffprobe / 抽格 / 音量）
```
